ArcheoGra Documentation


*Artwork generated by Google Gemini

Welcome to the documentation for ArcheoGra, a Julia package designed to reconstruct possible prehistoric human migration routes and social structures from archaeological data.

For the baseline of human presence, we use archaeological sites of confirmed human presence. From there, we model migration routes as edges in a spatial network, where the archaeological sites are the vertices of the network. Vertices are connected based on their distance. The framework for creating networks is discussed in (Hilpert, Brockmann, Maier, et.al., An interdisciplinary approach to mobility network building in Archaeology, in preparation). Different measures of distance are employed, ranging from a direct Haversine-distance to adjust for earth curvature, to a least-cost path (LCP) analysis reflecting realistic travel distances based on topographical data. We employ adaptive Wavelet methods to find LCPs using an adaptive Dijsktra's Algorithm, see Brockmann, Perlberg, Kunoth (2026) for a detailed description.

I have developed the ArcheoGra.jl package in connection with my Ph.D thesis at the University of Cologne (Multigrid Methods for Diffusion-Advection Equations on Metric Graphs: Creating Archaeological Networks and Modelling Migration Dynamics, 2026).

The package is divided into two main submodules. For functions shared by both modules see Shared Functions

1. Connect Network (ConNetw)

This submodule provides the foundational tools to construct networks from archaeological datasets. It handles the initial setup, global parameters, and fundamental data preparation required to model prehistoric mobility and social connectivity.

  • Read more: Connect Network Documentation

2. Least Cost Path Analysis (LCPA)

This submodule provides tools to calculate realistic travel distances between archaeological sites using topographical data. Instead of relying on straight-line distances (Haversine), the network models human movement based on energy expenditure, taking elevation changes into account. The submodule was developed in collaboration with Lena Perlberg (see Perlberg, 2025).
