Cost Functions and Adjacency Matrices

Before a path can be calculated, the topographical map must be converted into a weighted graph. The weights (costs) are determined by mathematical models of human movement.

Cost Models

ArcheoGra.LCPA.Tobler_Hiking — Function
Tobler_Hiking(S::Float64)

Calculates the hiking velocity using Tobler's Hiking function.

The function estimates walking speed based on terrain slope. It is generally defined for slopes between -60 and 50 degrees. The formula used is v = 6 * exp(-3.5 * |S + 0.05|), where S is the slope.

Arguments

  • S::Float64: The terrain slope (rise over run), where S = tan(angle).

Output

  • Float64: The estimated hiking velocity in km/h (bounded within (0, 6]).
ArcheoGra.LCPA.KS_Hiking — Function
KS_Hiking(S::Float64)

Calculates the hiking velocity based on the Kondo-Seino model.

This piecewise exponential model is derived from GPS-aided walking experiments on the historical Nakasendō-Kisoji road in Japan (Kondo & Seino, 2010). It differentiates between uphill/gentle downhill and steeper downhill slopes.

Arguments

  • S::Float64: The terrain slope (rise over run).

Output

  • Float64: The estimated hiking velocity in km/h.
ArcheoGra.LCPA.adjusted_Hiking — Function
adjusted_Hiking(S::Float64)

Computes an adjustment factor for hiking speed as a function of slope S.

For slopes S >= -0.07, the function uses a steeper logistic decay; for steeper downhill slopes (S < -0.07), a gentler decay is applied. This provides a relative cost factor describing the hiking speed, required for least-cost path calculations.

Arguments

  • S::Float64: Terrain slope (rise over run), positive for uphill, negative for downhill.

Output

  • Float64: Adjustment factor (typically between 0 and 1) describing the relative hiking speed.
ArcheoGra.LCPA.f_LloberaSluckin — Function
f_LloberaSluckin(S; cS=15)

Calculates a symmetric travel cost using the Llobera-Sluckin function.

Arguments

  • S::Number: The terrain slope (rise over run).

Keywords

  • cS::Number: Critical slope parameter (default: 15).

Output

  • Float64: The calculated symmetric travel cost.
ArcheoGra.distance — Method
distance(u::Tuple, v::Tuple)

Calculates the great-circle distance between two geographic coordinates using the Haversine formula.

Arguments

  • u::Tuple: A tuple (latitude, longitude) for the first point in degrees.
  • v::Tuple: A tuple (latitude, longitude) for the second point in degrees.

Output

  • Float64: The calculated geographic distance in kilometers.

Configuration Constants

ArcheoGra.LCPA.WeightConfig — Type
WeightConfig

A configuration container defining directional weighting and distance functions.

This structure specifies how vertical, horizontal, and diagonal relationships between grid cells are combined and normalized for graph construction.

Fields

  • vert_func::Function: Combination rule for vertical neighbors.
  • hori_func::Function: Combination rule for horizontal neighbors.
  • diag1_func::Function: Combination rule for the first diagonal neighbors (top-right to bottom-left).
  • diag2_func::Function: Combination rule for the second diagonal neighbors (top-left to bottom-right).
  • vert_dist::Function: Distance or normalization function for the vertical direction.
  • hori_dist::Function: Distance or normalization function for the horizontal direction.
  • diag1_dist::Function: Distance or normalization function for the first diagonal direction.
  • diag2_dist::Function: Distance or normalization function for the second diagonal direction.
  • symmetric::Bool: Set to true if weights are symmetric (w(u, v) == w(v, u)), false otherwise.

Example

# Simple additive configuration
cfg = WeightConfig(
    (a,b)->a+b, (a,b)->a+b, (a,b)->a+b, (a,b)->a+b,
    (a,b)->1.0, (a,b)->1.0, (a,b)->√2, (a,b)->√2,
    true
)

cfg.vert_func(1, 2)     # → 3
cfg.diag1_dist(1, 1.5)  # → 1.414...
ArcheoGra.LCPA.Kondo_Average — Constant
Kondo_Average

A pre-defined symmetric WeightConfig based on the Kondo averaging scheme.

This configuration defines symmetric weighting where simple addition is used to combine neighboring values, and constant factors (2 and √2) are used for spatial normalization. The final argument is set to true to declare that weights are symmetric.

Example

Kondo_Average.combine_x(1.0, 2.0)  # → 3.0
ArcheoGra.LCPA.Haversine_Config — Constant
Haversine_Config

A pre-defined asymmetric WeightConfig using the Haversine distance metric.

This configuration measures directed differences (a - b) and uses the real geographic distance between cell coordinates to compute slope-like relationships. The final argument is set to false to indicate non-symmetric weighting.

Example

Haversine_Config.dist_x(lat1, lat2)

Adjacency Matrix Generation

ArcheoGra.LCPA.weighted_adjacency_matrix — Function
weighted_adjacency_matrix(cost_raster::AbstractMatrix{<:Number})

Computes a symmetric adjacency matrix based on a cost raster grid.

The connectivity is determined using 8-neighbourhood relations. For horizontal and vertical neighbors, edge weights are calculated as the average cost of the two adjacent cells. For diagonal neighbors, edge weights are calculated as the average cost divided by √2.

Arguments

  • cost_raster::AbstractMatrix{<:Number}: A 2D matrix containing terrain costs.

Output

  • SparseMatrixCSC{Float64, Int}: A symmetric sparse adjacency matrix of size (m * n) × (m * n), where m and n are the dimensions of the input cost raster.
ArcheoGra.LCPA.weighted_adjacency_matrix_haversine — Function
weighted_adjacency_matrix_haversine(TopData::AbstractLCPAData, Cost_func::Function)

Constructs an asymmetric weighted adjacency matrix using Haversine distances and elevation differences.

Slope values between neighbouring cells are calculated using the geographic distance and elevation differences. These slope values are then passed through the provided cost function to determine the edge weights.

Arguments

  • TopData::AbstractLCPAData: Topographical data structure containing the cost map and boundaries.
  • Cost_func::Function: A function mapping slope (rise over run) to travel costs.

Output

  • SparseMatrixCSC{Float64, Int}: An asymmetric sparse adjacency matrix of size (m * n) × (m * n).
ArcheoGra.LCPA.weighted_adjacency_matrix_combi — Function
weighted_adjacency_matrix_combi(LCPAData::AbstractLCPAData, WConfig::WeightConfig; Cost_func::Function = x -> x)

Constructs an adjacency matrix combining a customizable weight configuration and a cost function.

Computes transition costs between adjacent cells by dividing the combined cell values by the directional distance, as defined in WConfig. The result is then evaluated using the provided Cost_func.

Arguments

  • LCPAData::AbstractLCPAData: Data structure containing the grid (e.g., CostMap).
  • WConfig::WeightConfig: Configuration defining interpolation and distance functions.

Keywords

  • Cost_func::Function: A function applied to the computed slopes (default: identity x -> x).

Output

  • SparseMatrixCSC{Float64, Int}: Sparse adjacency matrix of size (m * n) × (m * n).
