Data Structures and Input/Output

This section details the robust data structures used to store archaeological and source data, alongside the functions required to parse datasets from standard .toml, .csv, and .xlsx formats.

Core Data Structures

ArcheoGra.ConNetw.ArchDataEntry — Type
ArchDataEntry

Type that represents a data entry from an archaeological dataset. Stores essential information for each entry.

  • id: ID of stored entry. Created independently of possible IDs in existing datasets.

  • name: Name of the archaeological site.

  • coords: Coordinates of the archaeological site (longitude, latitude).

  • time_period: Time period of the archaeological site.

  • material_presence: List of names of present materials.

  • num_material_presence: IDs of materials found (ID corresponds to the Material Data Set).

  • material_multiplicity: Amount of findings of the respective material.

  • entry_classification: Possible prior classification or group assigned to the entry.

  • grid_id: Spatial grid identifier.

ArcheoGra.ConNetw.SourceDataEntry — Type
SourceDataEntry

Type that represents a data entry from the raw-material source dataset.

  • id: ID of the raw material source.

  • material_name: Name of the material found at this source.

  • coords: Coordinates of the raw material source (longitude, latitude).

  • grid_id: Spatial grid identifier.

ArcheoGra.ConNetw.Source_DataSet — Type
Source_DataSet

Container type for the source dataset.

  • Data: Vector of source data entries of type SourceDataEntry.

  • source_mult: Multiplier for weighting sources when calculating connections.

ArcheoGra.ConNetw.Arch_DataSet — Type
Arch_DataSet

Container type for the archaeological dataset.

  • Data: Vector of archaeological data entries of type ArchDataEntry.
ArcheoGra.ConNetw.MaterialEntry — Type
MaterialEntry

Type representing a specific material data entry.

  • material_id: Internal ID for the material in the local list of materials.

  • mat_prop: Property of the material entry consisting of the time period and distribution distance.

ArcheoGra.ConNetw.MaterialDataList — Type
MaterialDataList

Container type for material storage.

  • Material_list: Dictionary assigning a unique string identifier to a material entry.
ArcheoGra.ConNetw.file_props — Type
file_props

Type for storing properties of a dataset, including columns mapping for parsing data entries.

  • filePath: Path of the file. Can be a relative or absolute file path.

  • file_type: File type described as a string (e.g., 'xlsx', 'csv', 'txt').

  • sheetname: Excel only: Sheet name of the dataset.

  • delim: For delimited files: The delimiter character.

  • material_cols: Range of columns where material presence is stored.

  • material_age: String representation of the time period for the materials in the data.

  • material_distance: Transport distance of the material in the data.

  • grid_id: Column index containing the grid identifier.

  • long_ind: Column index containing the longitude.

  • lat_ind: Column index containing the latitude.

  • name_ind: Column index containing the name of the archaeological site (if available).

  • class_ind: Column index containing prior group classification (if available).

ArcheoGra.ConNetw.PreparedTimePeriod — Type
PreparedTimePeriod

Pre-indexed view of archaeological data for a single time period. Built once by prepare_network_data and reused by all network-creation functions, replacing repeated linear scans over the full dataset with O(1) lookups.

  • time_period: Name of the time period.

  • sites: Sites belonging to this time period.

  • site_indices: Indices of sites into the original Arch_DataSet.Data vector.

  • site_material_dicts: Per-site dictionary mapping material_id to multiplicity.

  • material_map: Per-material mapping material_id to a list of tuples (local_site_index, multiplicity).

I/O and Data Management

ArcheoGra.ConNetw.read_data_TOML — Function
read_data_TOML(config_file::String)

Reads a setup TOML file and creates the corresponding cumulative archaeological and material datasets.

When reading in data from the same time period across multiple files, it is recommended to use the identical time_period tag.

Arguments

  • config_file::String: The file path to the setup .toml file.

Output

  • Tuple{Arch_DataSet, MaterialDataList}: The fully initialized datasets parsed from the configuration.
ArcheoGra.ConNetw.read_data — Function
read_data(file::file_props; data::Arch_DataSet, MaterialData::MaterialDataList)

Reads archaeological dataset from an external file (XLSX, CSV, or TXT) into the internal structures. Updates the provided dataset and material lists dynamically.

Arguments

  • file::file_props: Configuration object defining the file path, type, and column mappings.

Keywords

  • data::Arch_DataSet: Existing dataset to append to (defaults to an empty dataset).
  • MaterialData::MaterialDataList: Existing materials list (defaults to an empty list).

Output

  • Tuple{Arch_DataSet, MaterialDataList}: The updated archaeological dataset and material list.
ArcheoGra.ConNetw.read_source_data — Function
read_source_data(toml_file::String, MatData::MaterialDataList)

Parses source raw material data from a TOML configuration and updates the global material dictionary.

Arguments

  • toml_file::String: Path to the .toml configuration file.
  • MatData::MaterialDataList: The existing material dataset to be updated.

Output

  • Dict{String, Tuple{Source_DataSet, Float64}}: Dictionary mapping time periods to their source dataset and multiplier.
ArcheoGra.ConNetw.add_data! — Function
add_data!(dataset::Arch_DataSet, data::ArchDataEntry)

Appends a new archaeological entry to an existing dataset.

Arguments

  • dataset::Arch_DataSet: The existing archaeological dataset.
  • data::ArchDataEntry: The new archaeological entry to append.

Output

  • Vector{ArchDataEntry}: The updated underlying data vector.
ArcheoGra.ConNetw.add_material! — Function
add_material!(entry::ArchDataEntry, material_presence::AbstractVector{<:AbstractString}, material_id::AbstractVector{<:Any}, material_multiplicity::AbstractVector{<:Any})

Functions adds material presence to an already existing entry in a dataset of archeological sites. Also adds material multiplicity of the corresponding materials. Function is required whenever an archeological sites is added at an already existing pair of coordinates.

Arguments:

  • entry::ArchDataEntry: Entry of archeological site where material presence will be added.
  • material_presence::AbstractVector{<:AbstractString}: Vector of material names which are added to existing site.
  • material_id::AbstractVector{<:Any}: List of IDs of materials which are added to existing site.
  • material_multiplicity::AbstractVector{<:Any}: Vector of multiplicity of the materials which are added to the entry.
ArcheoGra.ConNetw.num_entries — Method
num_entries(dataset::Arch_DataSet)

Returns the total number of archaeological entries in the given dataset.

Arguments

  • dataset::Arch_DataSet: The archaeological dataset to evaluate.

Output

  • Int: The number of entries.
ArcheoGra.ConNetw.num_entries — Method
num_entries(dataset::Arch_DataSet, property::Symbol, keyvalue::Any)

Returns the number of archaeological entries in the given dataset that match a specific property value.

Arguments

  • dataset::Arch_DataSet: The archaeological dataset to evaluate.
  • property::Symbol: The property symbol to check (e.g., :time_period).
  • keyvalue::Any: The specific value the property must match.

Output

  • Int: The number of matching entries.
ArcheoGra.ConNetw.get_coordinates — Function
get_coordinates(dataset::Arch_DataSet)

Retrieves a strictly typed list of coordinates and their corresponding time periods from the dataset.

Arguments

  • dataset::Arch_DataSet: The dataset containing archaeological entries.

Output

  • Vector{Tuple{Tuple{Float64, Float64}, String}}: A vector of tuples containing coordinates and time periods.
ArcheoGra.ConNetw.check_presence — Function
check_presence(coords::Tuple{Float64, Float64}, time::String, dataset::Arch_DataSet)

Checks if a specific pair of coordinates for a given time period is already present in the dataset.

Arguments

  • coords::Tuple{Float64, Float64}: The coordinates to check as (longitude, latitude).
  • time::String: The time period string.
  • dataset::Arch_DataSet: The dataset to search.

Output

  • Bool: true if the coordinate and time period combination exists, false otherwise.
ArcheoGra.ConNetw.get_material_id — Function
get_material_id(material_presence::Vector{String}, materiallist::MaterialDataList)

Maps a list of material names to their corresponding internal IDs based on the material dataset.

Arguments

  • material_presence::Vector{String}: Vector of material names.
  • materiallist::MaterialDataList: The dataset defining the materials and their IDs.

Output

  • Vector{Int}: Vector of corresponding material IDs.
